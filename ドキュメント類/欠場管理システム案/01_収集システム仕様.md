# Jリーグ欠場・復帰情報台帳：収集システム仕様 v0.1

2026-10-24／仕様整理版。実装・配備・定期実行設定は未実施。

追加確定条件：動作環境は手元MacまたはWorkのみ。追加課金の検索・AI API・クラウドは使わない。以下のサービス・費用に関する検討はこの条件内で行う。Workから自作アプリへの無人連携は未検証。公式ニュースの取得検証は「04_公式ニュース実取得の検証結果.md」を参照。

## 1. 目的と境界

個人用のブラウザ画面で、J1・J2各クラブの離脱選手と経過を管理する。公式ニュースを収集・定型化して保存し、登録選手の後追い検索で復帰・長期化・引退・移籍などの情報を追加する。戦力の数値評価、勝敗予測、買い目作成は既存システムが担う。

主画面は未終了の離脱案件の一覧とする。システムは復帰候補を提示し、利用者が根拠を確認してチェックすると復帰ステータスになり、主画面から外れる。履歴は残す。続報なしや検索失敗で選手を外さない。予想側では日付で欠場影響が減衰するため、主画面と予想上の戦力除外は一致するとは限らない。

本書の「要件」は会話の目的から導いた実装要件。「初期案」は利用者未決定の運用提案。未決事項を勝手に確定して運用開始しない。独立して進められる開発は継続する。

## 2. 初期版の範囲

必須：既存データの取り込み、公式ニュース収集、選手・案件への定型化、経過の蓄積、選手名による後追い検索、復帰候補提示と利用者確認、一覧・詳細・確認待ち画面、CSV出力と差分、収集の成否表示、バックアップ・復元。

対象クラブはシーズンごとの公式所属に基づいて管理する。実装は少数クラブで縦に動作検証してから全対象へ展開する。全クラブの収集元が検証されるまで全件対応と表示しない。

既存card・病気のデータは欠落させず取り込む。card・病気の自動収集を初期版の必須範囲に含めるかは未決。拡張できるデータ構造にする。公式試合記録によるベンチ入り・出場の照合は追加候補であり、取得経路は未検証。

## 3. 情報源と収集

- 一次収集：Jリーグ公式ニュース、各クラブ公式ニュースのトップチーム関連。
- 後追い：公式サイト内のインタビュー・練習記事・試合記事等と、選手名によるネット検索。報道は出典区分を分ける。
- 情報源台帳：発表元ID、URL、クラブID、対象カテゴリ、一覧・ページ送り方式、取得方式、取得条件の確認日、対象期間、最終成功日時、最新記事日時、失敗理由、再試行状況。
- 一覧から記事を発見し本文を取得する。タイトルの語句だけで登録・復帰判定しない。
- 本文から広告・関連ニュース・プロフィール等を除く。同じ記事を再取得しても重複登録しない。追記・訂正は本文領域の変更として履歴化する。
- 記事の途中で失敗した場合、全件成功として進捗を確定しない。再試行・期間指定の取り直しができる。
- サイト別の取得方式は実際の構造・利用条件を確認して選ぶ。公開RSS等が存在する前提にしない。本文保存範囲も確認する。

初期案：公式ニュースは毎日朝夕、後追い検索は1日1回。日本時間で設定可能。見込み日前後・新情報ありの選手を優先。手動実行と選手単位の再検索を用意する。実行場所と費用上限は未決であり、定期実行はまだ有効化しない。

## 4. 保存するデータ

| 単位 | 主な項目 |
|---|---|
| 選手 | 内部ID、公式名、表示名、別名、CSV名、公式プロフィール、所属履歴 |
| クラブ | 内部ID、公式名、別名、CSV名、大会所属の有効期間 |
| 記事 | ID、発表元、URL、タイトル、公開日時、取得日時、本文更新版、保存可能な根拠箇所、取得状態 |
| 離脱案件 | ID、選手ID、欠場理由、診断名、受傷日、手術日、離脱開始日、期間原文、上下限・単位、期間の起算日、採用見込み日、採用根拠、管理状態 |
| 経過イベント | 案件ID、種別、発生日、根拠記事・箇所、抽出内容、抽出版、検証状態 |
| 判断 | 対象、変更前後、利用者の確認・保留・却下、確認日時、有効日、理由、根拠 |
| 検索実行 | 選手・案件、検索語、実施日時、結果、取得失敗、費用・利用量（取得可能な場合） |
| 出力 | 出力ID、日時、版、対象行、前回との差分、検証結果、ファイル識別情報 |

記事の事実、システムの推論、利用者が採用した値を別保存する。内部の日付は年4桁で保持し、日本時間の表示とイベント日を区別する。不明は空値として保持し、0日・当日で代用しない。

全治は「記載あり／未定と明記／記載なし」を区別。週・暦月・日、範囲、約・予定の修飾を保存する。起算日が曖昧なら計算結果は確認候補にする。既存の負傷別判断目安は推定値として取り込めるが公式情報と混ぜない。単一のCSV日付に採用する方針は設定と確認履歴に残す。

## 5. 選手照合と案件の統合

- 氏名の空白・全半角・異体字は照合用キーで正規化し、原表記も保存する。
- 所属・時期・プロフィール等を併用し、同姓同名や曖昧な外国籍表記は要確認にする。
- Jリーグとクラブの同じ発表は、同一案件に複数の根拠として関連付ける。
- 同一選手でも再負傷・別部位・別の発生日は別案件候補とする。不確かな統合は確認へ回し、統合解除も履歴付きで可能にする。
- 同じ記事に複数選手がある場合、選手ごとに分割して正しい根拠を関連付ける。
- 既存CSVの各行は元行ID付きで保存し、移行直後に勝手な統合・削除・復帰確定を行わない。

## 6. 状態と利用者操作

案件の管理状態と、経過イベント・確認待ち・情報鮮度を独立させる。

| 管理状態 | 意味・表示 |
|---|---|
| 未終了 | 主画面に表示。最新根拠として離脱・練習合流・出場情報等を併記 |
| 復帰確認済み | 利用者が復帰チェック。有効日と根拠を記録し、主画面から外す |
| 管理対象外 | 引退・対象外への移籍等を利用者が確認。有効日・終了理由を記録 |
| 登録取消 | 誤登録として理由を残す。復帰とは扱わない |

経過種別は負傷、診断、手術、離脱継続、リハビリ、部分合流、全体練習合流、ベンチ入り、試合出場、再負傷、引退、移籍等。

復帰候補の提示は「全体練習合流を確認」「公式戦出場を確認」等の理由と根拠を必須とする。候補採用時に復帰有効日を確認する。不明なら利用者が判断日を採用できるが、手動設定と記録する。複数の未終了案件があるときは確認対象を明示し、他案件を黙って終了しない。

引退発表が将来の引退を指す場合は即時終了しない。対象クラブ間の移籍では所属変更を行い追跡を継続する。確認の取消・訂正は履歴を残し可能にする。

「続報なし」「検索未実施」「検索したが該当なし」「取得失敗」「見込み日経過」「情報競合」は独立した表示。長く情報がないことを離脱継続や復帰の新しい根拠にしない。

## 7. 後追い検索

氏名・別名・クラブ名と復帰関連語を組み合わせ、未終了案件を中心に検索する。対象時期を指定し、発生日と記事公開日を分離する。

本文未確認の検索結果は未検証と表示し、復帰確定しない。過去の負傷回想、期限付き移籍からの復帰、チームの昇格、別人を除外する。最新の再負傷と競合する復帰記事は両方を提示する。却下した同一候補は再通知せず、記事の重要な変更時だけ再提示する。

検索サービス・文章抽出方法は未選定。プロバイダーを差し替えられる構成とし、失敗時は台帳保持と手動URL登録で作業を続けられる。自動検索未接続の段階を完成とは呼ばない。

## 8. 画面

1. 未終了一覧：クラブでまとめ、選手名、欠場理由、開始日、採用見込み日、最新経過、最新根拠日、検索最終実施日を表示。クラブ・理由・復帰候補・見込み日経過で絞り込み。
2. 確認待ち：提案内容、根拠、変更前後を比較し、採用・保留・却下。新規離脱の登録方式は未決。初期案は候補として保存し、採用後にCSV対象にする。
3. 選手詳細：所属・案件ごとの時系列、根拠記事、推定と公式値の区別、手動修正・復帰確認・管理終了・取消。
4. 出力：CSVプレビュー、前回との差分、行ごとのエラー・出力保留理由。出力と予想への反映は別表示。
5. 収集状況：情報源別の成功・失敗・対象範囲、再試行。全件未取得でも「更新済み」と一括表示しない。

台帳の主画面から外れたことだけを、既存予想に反映済みの証拠にしない。

## 9. 移行とCSV

元Excel・CSVは変更しない。初回取り込み時に件数・列・元値と行識別子を記録する。日付経過のみで復帰済みと判定しない。元169行を保存し、元のcard・病気・メモも保持する。

互換CSVの列順は次の10列：season, origin_competition_key, applies_across_competitions, team, player_name, absence_type, start_date, expected_weeks, expected_return_date, note。

UTF-8 BOM付き、日付yy/mm/dd。固定値は元データを維持し、新規大会設定は利用者設定を使う。note見出しは正規名への変更案を読み込み検証で確認する。改行・カンマ・日本語の引用を正しく扱う。

不明な日付・競合・重複を黙って修正したり、出力から黙って落とさない。対象行数・保留行数・理由を提示する。継続中で全治不明の場合の出力値は未決であり、無期限の日付を捏造しない。互換出力と正確な復帰連携の違いは「02_予想システム連携要件.md」に記載する。

## 10. 運用と受入条件

個人専用アクセスとする。保存先・実行環境は未決。最初の検証を手元PCで行う初期案はあるが、本運用の決定ではない。画面を閉じても更新できる実行方法と、PC停止・障害後の取り直しを用意する。費用上限、バックアップ保存先・頻度を設定する。

受入条件：

- 実例の複数選手・期間幅・日付不明を捏造なく抽出する。
- 同一記事の再取得・訂正・重複情報で案件が増殖せず、根拠を保持する。
- 復帰確認の前後で主画面・履歴が正しく切り替わり、取消できる。
- 続報なしや取得失敗でも選手と手動判断が消えない。
- 既存データを件数と元値で照合でき、CSV差分を確認できる。
- ネット検索を実際に実行し、候補を保存・再取得できる。手動の模擬検索だけで完了にしない。
- 再起動とバックアップ復元後も案件・判断・出力履歴を保持する。
- 収集元の検証済み／未検証を明示する。
