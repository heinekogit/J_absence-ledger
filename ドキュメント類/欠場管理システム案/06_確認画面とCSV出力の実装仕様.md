# 確認画面・保存・CSV出力：実装仕様 v0.1

2026-10-24。実装者向けの具体化資料。アプリは未作成。本書は01の詳細仕様、02は予想連携の境界、05は抽出検証の根拠として併読する。

## 1. 前提

利用者1人、手元Macのブラウザで利用する。追加課金の検索・AI API・クラウドを使わない。Workでの読解結果は手動登録できるようにするが、Workからの無人連携を前提にしない。

ローカル試作の構成案：Mac上のサーバー、SQLite、ブラウザ画面。保存はブラウザ内だけで完結させない。ローカルサーバーは127.0.0.1に限定して待ち受ける。実装言語・フレームワークは実装者が選定理由を提示して決める。クラウド公開はしない。

本書で新たに具体化した操作・画面は実装案であり、受け入れテスト時に使い勝手を確認する。予想システムの変更、元Excel/CSVの上書き、定期実行開始は含まない。

## 2. 最小構成の画面

### A. 離脱中一覧（起動時の画面）

上部：選手名検索、クラブ選択、欠場理由、確認待ちあり、見込み日経過、最終収集結果。件数は選手数と案件数を区別する。

表の列：クラブ／選手／欠場理由・診断／離脱開始日／採用復帰見込み日／最新経過／最新根拠日／確認待ち。クラブ順に並べ、選手名から詳細を開く。不明な日付は「不明」とし、0・当日・仮の遠い未来日に置換しない。

復帰候補は一覧に残り、「復帰候補」と表示。見込み日経過だけでは消さない。「予想側の欠場係数は減衰する場合あり」と説明し、戦力復帰済みと断定しない。

主な操作：「候補を確認」「CSV出力」「公式ニュースを取得」「手動登録」。収集は処理中・成功・一部失敗を表示し、失敗時も既存一覧を保持する。

### B. 確認待ち

分類：新規離脱、追加経過、復帰候補、見込み日修正候補、対象外候補、重複候補。

各候補には、選手と所属、提案内容、元記事タイトル・発表元・公開日・URL、保存した根拠箇所、抽出日時を表示する。現採用値と候補値を左右に比較。不明値と推定値は見分けられるようにする。

操作：採用、訂正して採用、保留、却下。却下理由は任意だが、選手違い・過去記事・重複等の選択肢を用意する。訂正箇所は手動修正と記録し、抽出原値は残す。保留・却下を新しい収集で勝手に採用しない。

初期案は新規離脱も確認後に有効化する方式。取り込み候補は保存するが採用前は予想用CSVに混ぜない。利用者が新規自動採用を希望した場合だけ方針を変更する。

### C. 選手・案件詳細

選手の所属、別名、CSV表記、案件ごとの状態と診断、公式期間、採用見込み日、根拠を表示する。その下に経過を発生日順で表示し、公開日・取得日も確認可能にする。発生日不明は別表示し、取得順で架空の経過を作らない。

操作：「経過・URL追加」「採用値を修正」「復帰確認」「管理対象外」「登録取消」「判断履歴」。手動情報ではURL未入力も許すが、根拠種別を「利用者判断」とし理由を必須にする。

採用期間と日付の変更は、元の公式情報を置換せず採用値だけ更新する。取り直しや後追い検索で手動採用値を上書きしない。変更提案として保存する。

### D. CSV出力

まずプレビューを作る。基準日時、出力対象の範囲、出力方式、行数、保留数を表示する。前回成功出力に対して追加・変更・削除を一覧表示し、削除理由も確認する。

出力方式は当初「既存10列互換」。この形式には復帰確認有効日を明示する列がなく、既存予想には減衰処理がある。互換出力だけで正確な復帰連携が完成したと表示しない。

「CSVをダウンロード」で新しいファイルを作成する。既存予想フォルダへ自動配置しない。出力履歴には基準・対象案件の版・ファイルハッシュ・件数を残す。ダウンロード後の表示は「出力済み」であり「予想へ反映済み」ではない。

### E. 履歴・収集状況

復帰確認・対象外・取消の履歴を閲覧し、必要なら訂正する。情報源ごとの対象範囲、最終成功、失敗内容、候補件数、再実行を表示。過去ページ未取得の情報源を網羅済みと表示しない。

## 3. 復帰確認の操作

1. 復帰候補または詳細から「復帰確認」を押す。
2. 根拠と経過種別（練習合流／ベンチ入り／試合出場／その他）を表示する。
3. 対象案件と復帰有効日を選ぶ。有効日が不明なら入力を求める。「確認日を採用」の明示操作は可能だが、推定ではなく利用者指定日と記録する。
4. 「復帰確認にチェック」を入れ、「確定」で保存する。
5. 対象案件を復帰確認済みへ変更し、主画面から外す。履歴へ移し、他に未終了案件があればその選手は一覧に残す。

必須項目は対象案件、有効日、根拠記事または利用者判断理由。確認日時は自動記録。複数案件を終了する場合は明示的に選択する。後日取り消した場合も旧判断を残す。引退・対象外移籍は別操作で終了理由と有効日を持つ。

## 4. 不明値・推定・重複

### 日付

受傷日の原文、正規化した完全日付、日付の精度（年月日／月日／日のみ／不明）、推定候補、利用者採用値を分ける。公開年を使った年補完は推定候補とし、元の原文には混ぜない。発表日と受傷日を入れ替えない。

全治の原文、下限・上限、単位、起算日、起算日の根拠を保存する。暦月を一律4週に換算しない。公式全治からの計算も実際の試合復帰の保証とはしない。

期間幅の採用、全治不明時の既存目安の採用は自動確定しない。初期版では候補編集で利用者が採用日を指定し、理由を保存できる。将来の自動採用ルールをこの手入力の背後に隠さない。

### 重複

正規化URL・記事ID・本文版で同じ記事の再取得を判定する。異なる記事間では同じ選手・所属・診断と元記事リンク等を根拠に案件関連付けの候補を作る。

既存案件に追加するか新規案件にするかを確認できる。同じ名前と診断だけで再負傷を統合しない。統合・解除で根拠記事を失わない。実装初期の自動関連付けは同一記事の再取得に限定し、異なる記事間は確認候補にする案。

## 5. 永続保存と整合性

保存単位：選手・所属履歴、情報源、記事と本文版、抽出候補、離脱案件、経過、判断履歴、収集実行、出力履歴。内部IDを持ち、表示名変更で関連が切れないようにする。

1回の採用は案件更新・根拠関連付け・判断履歴をまとめて確定する。途中失敗なら全体を取り消し、不完全な採用を残さない。二重クリックで同じ判断や案件を重複作成しない。複数タブで古い候補を採用した場合、版競合を知らせ再確認させる。

記事・抽出値は再取得で変更されても過去版を保持。利用者判断は追記で残す。バックアップはデータベースが整合する方式で作り、復元を実際に確認する。保存先・バックアップ先は起動案内に明示する。

## 6. CSV出力の契約

列順：season, origin_competition_key, applies_across_competitions, team, player_name, absence_type, start_date, expected_weeks, expected_return_date, note。

UTF-8 BOM付き。日付yy/mm/dd。数値欄に単位を入れない。noteは正規の列名として読み込み互換性を隔離環境で確認する。クラブ・選手名は既存システムの照合表記に合わせる。原データや未知の値を黙って変えない。

### 出力判定

| 行の状態 | 初期版の扱い |
|---|---|
| 既存から移行し、値を変更していない | 既存値を維持する候補。ただし日付書式・必須項目・重複を検査 |
| 新規離脱の未採用候補 | CSVには含めず、保留件数に表示 |
| 採用済み・必要な値が揃う | CSV対象 |
| 受傷日・採用見込み日が不明 | 要確認。既存形式で影響が0になり得るため黙って出力しない |
| 重なる複数案件・所属不明 | 要確認。二重計上や誤所属のまま出力しない |
| 復帰確認済み・対象外 | 下記の出力履歴方針を決定するまでは変更を保留として提示 |

保留行がある状態で、既存ファイルを完全置換してよいと案内しない。出力前に、保留の解消または「既存の採用値を継続する」という明示選択が必要。未確定部分だけ落としたファイルを通常の完成出力として渡さない。検証用の部分CSVは「検証用」と明示して別出力できる。

### 未決だが画面実装を妨げない事項

復帰済み行を除く現時点一覧にするか、過去案件を含めるかは予想側の再計算・スナップショット運用と合わせて選ぶ。初期実装では出力プレビューと差分まで進め、終了案件による削除は保留理由を表示する。02の拡張方式を採用するまでは復帰チェックを10列CSVだけで完全に表現できると約束しない。

## 7. 最初に作る縦の動作

1. 既存169行を読み取りで移行し、件数・元値・元行IDを照合する。既存の過去行を日付だけで復帰済みにしない。
2. 少数クラブの実記事から候補を保存し、元記事と抽出結果を比較する画面を表示する。
3. 新規採用、訂正、保留、却下、追加経過、復帰確認、確認取消を一通り動かす。
4. CSVプレビューと前回との差分を表示し、未確定事項のない検証データで出力する。
5. 再起動・バックアップ復元・同じ記事の再取得で結果が保たれることを確かめる。

この区切りの後、全クラブの情報源・未知記事評価・無料範囲での後追い運用を広げる。保存画面だけで全システム完成とはしない。

## 8. 受入シナリオ

| シナリオ | 期待結果 |
|---|---|
| 鳥栖の3選手記事 | 3候補、別々の診断・期間・不明日付を保持 |
| Jリーグと川崎の野田選手 | 同一案件候補として2記事を表示し、採用後は1案件・2根拠 |
| 全治未記載・受傷日不明 | 勝手な日付生成なし。確認待ちとCSV保留理由が見える |
| 全治6〜8週 | 幅を保持し、単一採用日の根拠を利用者が設定できる |
| 期限付き移籍中の発表 | 発表元と所属を区別し、所属を確認できる |
| 復帰確認・取消 | 一覧→履歴→一覧へ戻り、判断履歴を失わない |
| 同じ選手の複数案件 | 1案件の復帰だけで選手全体を一覧から消さない |
| 手動修正後に記事再取得 | 手動値を上書きせず、新しい提案として表示 |
| 二重クリック・競合タブ | 重複判断なし。古い版は再確認 |
| CSVに改行・カンマ・日本語 | 再読込で値・列数・件数が一致 |
| 収集失敗・サーバー再起動 | 台帳が消えず、最終成功と失敗を区別 |
| CSVダウンロード | 「出力済み」と表示し、予想反映済みとしない |

## 9. 次に利用者へ確認する事項

実装開始時にMacでの起動・保存先、新規採用の確認方式、終了案件のCSV出力方針を確認する。先に確認画面と保存の動作を作り、具体例を見ながら選べるようにする。追加費用を使う案は出さない。仕様の未決事項を理由に、関係しない検証や画面実装まで止めない。
