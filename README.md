# Jリーグ欠場・復帰情報台帳（ローカル試作）

仕様と今後の検討事項は [台帳仕様と検討記録](ドキュメント類/欠場管理システム案/00_台帳仕様と検討記録.md) に集約します。

Python 3.11以降のみで動く個人用アプリです。`127.0.0.1` に限定して待ち受け、SQLiteに保存します。追加課金はありません。公式サイトへの手動取得時には通常の通信が発生します。

```sh
python3 app.py
```

登録済み情報源の公式ニュース初頁をまとめて取得する場合は、次を実行します。情報源ごとの成否をJSONで表示し、失敗・一部失敗があれば終了コード1を返します。記事は確認候補まで保存し、案件へ自動採用しません。

```sh
python3 app.py collect
python3 app.py collect --source-id 1 --source-id 2
python3 app.py collect --archives --max-pages 2
python3 app.py collect --archives --since-year 2026 --max-pages 2
python3 app.py collect --archives --source-id 6 --max-pages 2
```

長崎公式の過去一覧は、記事カードの掲載日を見出しと別に読み取ります。年をまたぐページでは対象年の記事だけを取得し、そのページで自動巡回を停止します。

町田公式のトップチーム一覧は、画面にページ番号リンクが表示されませんが、検証済みの `/page/N/` で次の一覧を取得できます。各記事の掲載日時を確認して対象年だけを収集し、古い年に達したら停止します。

藤枝MYFC公式は現行のトップチームニュース一覧を対象にします。ページ番号順に2026年の一覧を確認し、2025年の記事に達したページで巡回を停止します。負傷記事の「負傷日」「診断」「全治・復帰までの期間」を候補に抽出します。

ジュビロ磐田公式のニュース一覧は、この環境では記事一覧の代わりに404画面を返します。暫定的に公式トップ頁の最新ニュースリンクだけを収集元とし、過去記事や全記事の取得範囲には含めません。個別に確認したクラブ公式記事URLは画面から取得できます。

ガンバ公式の追加一覧はURL内の年月と記事の掲載年が一致しないことがあります。記事カードの日付を優先して対象年を判定し、前年の記事に達したら停止します。収集状況の「年境界まで確認」は登録済み一覧と見出し条件の範囲を示します。

`--archives` は公式一覧から発見済みの未取得過去ページを情報源ごとに指定件数まで辿ります。`--since-year` の既定値は2026年です。年月付きURLは対象年より前を除き、番号だけのページ送りは掲載日の確認できないページまたは対象年より前の記事が混在するページで停止します。日付を確認できない記事は自動取得せず、期間外の記事を案件に入れない設計です。取得済みページは再取得せず、結果と次のページ候補を収集履歴へ記録します。記事は確認候補に留まり、自動採用しません。ページ送りが見つかっていない情報源や、見出しに収集語句がない記事は対象になりません。

ブラウザで http://127.0.0.1:8765 を開いてください。保存先は `data/ledger.sqlite3` です。元の予想プロジェクトやCSVは書き換えません。既存CSVの移行は画面の「移行」からプレビューを確認して実行します。

新規記事は候補に留まり、利用者の採用まで一覧や互換CSVに入りません。終了案件のCSV扱いと、日付不明の出力は保留にします。CSVダウンロードは予想への反映を意味しません。

「定期収集管理」では収集曜日の変更、有効・無効の切替、手動実行、実行履歴、失敗した情報源、確認待ちの増減を確認できます。初期設定は火曜・金曜の週2回、日本時間9時です。木曜または金曜の週1回にも変更できます。MacのLaunchAgent `jp.local.j-absence-ledger.collect` が毎日9時にジョブを起動し、台帳内の設定に一致した曜日だけ実行します。アプリのWeb画面が閉じていても、Macにログインしていて起動していれば実行できます。スリープ中に予定時刻を過ぎた場合は、macOSが起床時にジョブを起動し、未実行の直近予定日を収集します。複数回分は最新の1回にまとめます。電源断の間は起動されません。初頁の収集上限は情報源ごとに50記事です。記事は確認待ちに留まり、自動採用しません。手動実行は曜日設定に関係なく動きます。実行結果は `data/ledger.sqlite3` と `data/collection-launchd.log` に記録します。

「選手名簿」は予想プロジェクトが取得した `jleague_club_players.csv` を読み取り専用で版付き保存します。原本ハッシュ、取得時刻、クラブ別の選手を残し、同じ原本の再取込は重複させません。J1・J2の対象40クラブ、空氏名、同一クラブ内同名、取得日の混在、極端に少ないクラブを取り込み前に検査します。離脱中案件との氏名・所属一致、別クラブ一致、氏名未発見を表示します。表示は確認候補であり、選手IDの確定、移籍・引退・復帰の自動判断や案件の所属変更は行いません。新しいCSVができたら同画面のボタンで再取込できます。

「CSV」画面の「暫定10列CSVをダウンロード」は、元の予想CSVと同じ列順で、日付と大会キーが確定している未終了案件だけを出力します。保留案件と未採用候補は含みません。画面で件数と保留理由を確認してください。全件が確定した場合の「CSVをダウンロード」も引き続き利用できます。予想入力の互換性を保つため、案件ID、根拠URL、確認状態などの新列は本体に追加しません。

復帰見込み日が日本時間の今日より前になった案件は、未終了でも暫定CSVから保留します。見込み日超過は復帰の証明ではないため、案件の状態は自動変更しません。保留理由に「復帰見込み日を経過」と表示し、最新の出場・練習・クラブ発表を確認してから更新してください。

画面では、公式ニュース初頁の手動取得、公式記事URLの取得、選手単位の公開検索、手動経過候補、採用・保留・却下、案件の修正、復帰確認と取消、CSVプレビューと差分を操作できます。検索にはDuckDuckGo Liteの公開ページを使います。検索結果は本文未確認として保存され、公式記事の本文取得後も確認候補に留まります。検索ページの構造変更や利用制限時は失敗を履歴に記録します。

「出場停止の消化確認」では、未終了のカード案件の対象日・クラブ・大会・節をＪリーグデータサイトの公式試合結果一覧と照合します。スコアと公式記録リンクが確認でき、単一試合の停止と分かる案件だけを消化候補に表示します。候補を開くと日付・対戦・根拠URLを案件画面に入力しますが、利用者が公式記録と処分を確認してチェックするまで案件を終了しません。予定試合、照合不能、複数試合・期間停止は未確定のまま表示します。照合は画面のボタンによる手動実行です。

「出場停止」画面の「最新の出場停止を取得」は、Ｊリーグデータサイトの最新のお知らせからJ1・J2の選手行だけを読み取ります。既存カード案件や未処理候補との重複を除き、新規分を「確認待ち」に保存します。J3選手と役員は対象外です。取得だけでは案件への採用、CSVへの出力、処分消化は行いません。対象ページは最新のお知らせ1件であり、過去分の網羅や定期実行は含みません。

「収集状況」には、2026年の年境界まで確認した情報源、未取得ページのある情報源、過去ページ未確認の情報源を区別して表示します。保存済みの掲載日があれば最古の日付を、月別URLだけが分かる場合は最古の確認月を示します。これは登録した一覧と見出し条件で確認した範囲です。

現時点で登録した情報源はJリーグJ1/J2と38クラブです。2026/27シーズンのJ1・J2計40クラブのうち、東京Ｖ・清水のクラブ公式一覧は未登録です。東京Ｖは旧ニュースURLが別サイトのトップへ転送、清水は取得時に証明書エラーまたはトップへの転送があり、収集経路を確定できていません。宮崎は `https://www.tegevajaro.com/news?page=1&year=2026` で2026年の一覧を取得でき、24ページの470見出しを記録しました。傷病記事2件の本文はサイト内の埋め込みデータから抽出し、受傷日の完全日付がない確認待ち候補としています。登録済みクラブでも記事カードの構造やページ送りによる取りこぼしがあります。全クラブ・全期間の収集と予想システムの改修は未実装です。開始日を訂正して復帰見込み日の根拠を再評価する案件は、一覧と詳細に「要再評価」と表示します。

バックアップは画面からSQLiteの整合したコピーをダウンロードできます。復元はサーバー停止中に `data/ledger.sqlite3` を別名で退避してから、バックアップファイルを同名へ置き換えます。

検証: `python3 -m unittest -v`。隔離DBで移行、候補の重複防止、復帰と取消、CSV引用、バックアップ復元を確認します。
